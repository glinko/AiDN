# Repository Structure Audit — 2026-08-28

## Scope

This is a code and documentation-structure audit of the AiDN repository at
commit `4e2c7bb`. It is an architectural planning record, not a claim that the
system has been behaviorally revalidated by this document alone.

## Observed health

- The package has clear domain directories for consensus, registry, ledger,
  providers, sessions, validation, rewards, MCP, snapshots, and operator
  surfaces.
- CI is green for lint, hermetic Python tests, Faucet tests, operator/dashboard
  builds, and isolated package installation.
- The repository has a reproducible Python lockfile and separate web/service
  dependency locks.
- The main risk is not a lack of domain concepts. It is concentration of too
  many workflows at a few boundary modules.

## Dependency boundaries to repair

The static import scan found five internal cycles. They are manageable today,
but they make independent testing and later decomposition harder.

1. `service` ↔ `runtime_protocol` ↔ `operator_read_models`:
   extract runtime-facing ports and response DTOs into a dependency-neutral
   contract module.
2. `ledger.service` ↔ `testnet_participation` ↔ reward preflight:
   make testnet participation an operation producer; let ledger own validation
   and finality, while a projection/dispatcher observes committed outcomes.
3. `main` ↔ `mcp`:
   make MCP receive an already-built application service instead of importing
   the application builder.
4. `domain.models` ↔ `runtime_parameter_policy`:
   move policy-independent model types into `domain` and policy DTOs into a
   dedicated contract module.
5. `operator_cometbft` ↔ `operator_cometbft_install`:
   extract shared configuration/value objects, then keep install and runtime
   control one-directional.

## Documentation findings

- There are 227 Markdown documents; 118 are date-stamped, acceptance, drill,
  rollout, evidence, or simulation records. These must remain discoverable but
  must not visually compete with current instructions.
- The root README contains a manually selected list rather than a complete
  navigation model.
- `docs/` lacked an index page; `docs/INDEX.md` is now generated by
  `tools/generate-docs-index.py` and classifies every in-scope document.
- `UX-0003` is assigned to two separate documents. Renumber the readiness
  wizard to a fresh UX identifier before the next external release.
- Several older RFC headings omit their identifier even though their filenames
  are correctly named. Standardize headings when those documents are next
  substantively edited; avoid churn-only edits to normative text.

## Repository hygiene findings

- Current working trees can collect built dashboard assets, Python
  `*.egg-info`, and local `bundles.json`. Decide explicitly whether dashboard
  output is a checked-in release artifact or a generated local artifact, then
  make the build destination and `.gitignore` match that decision.
- Do not broadly ignore `src/aidn_hypervisor/static/react-dashboard/assets/`
  until the release packaging path has been made explicit: some artifacts in
  that directory are intentionally tracked today.

## Recommended execution order

1. Establish the architecture boundary tests and small port/DTO packages for
   the five cycles; do not move behavior yet.
2. Split `api.py` into route modules and keep one compatibility-level router
   factory. This has the lowest consensus risk and immediately improves review
   quality.
3. Split `HypervisorService` by application workflow while leaving a facade for
   existing callers.
4. Decompose `LedgerOperationService` one operation family at a time, with
   golden state-transition tests before and after each move.
5. Split registry and operator access surfaces after their public contracts are
   covered by contract tests.
6. Formalize generated-artifact policy and consolidate historical documents
   under their existing paths through the documentation catalog rather than a
   disruptive file migration.

## Guardrails

- No consensus, ledger, wallet, or payment behavior changes are bundled with
  structural moves.
- Each extraction must preserve public imports or provide a short-lived,
  explicitly tested adapter at the boundary.
- Add a module-size and import-cycle check to CI only after a baseline is
  ratcheted down; a hard limit before decomposition would create noisy work.
