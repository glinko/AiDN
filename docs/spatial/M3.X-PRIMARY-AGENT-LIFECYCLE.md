# M3.2–M3.6 — Primary Agent lifecycle

M3 closes the first useful Primary Agent vertical path after the Node-scoped
slot seam from [M3.1](./M3.1-PRIMARY-AGENT-SLOT.md). The browser owns neither
credentials nor authoritative state: it sends typed, authorized plans and
renders the Node-owned slot/state projections.

## Delivered modules

- `web/operator-dashboard/src/spatial/data/primary-agent-binding.ts` — inspect,
  plan, apply, replace, suspend, detach, revoke, health, recovery, idempotency,
  stale-revision conflicts, audit-safe binding-changed events.
- `web/operator-dashboard/src/spatial/data/primary-agent-delivery.ts` — typed
  grants, allowlisted capability categories, binding-owned Hook subscriptions,
  redaction, cursor-based retained inbox, acknowledgement, retry,
  dead-letter, replay, and grant-changed events.
- `web/operator-dashboard/src/spatial/data/primary-agent-state.ts` —
  authoritative operational-state aggregation with explicit precedence,
  freshness, source, timestamp, and monotonic revision.
- `web/operator-dashboard/src/spatial/data/primary-agent-presence.ts` — live
  Presence view model, configurable material mapping, attention overlay,
  reduced-motion/quality fallback, accessible label, and last-seen evidence.
- `web/operator-dashboard/src/spatial/workspace/PrimaryAgentManagementSurface.tsx`
  — DOM-only management surface reusable inside the Spatial frame and a
  Classic fallback composition.

The event gateway routes `spatial.primary-agent.binding-changed.v1`,
`spatial.primary-agent.grant-changed.v1`, and
`spatial.primary-agent.state-changed.v1` through the existing query/cache
boundary. The renderer receives only `PrimaryAgentPresenceViewModel`; it never
opens transport or mutates Node state.

## Safety invariants

1. A plan is bound to `node_id`, `slot_id`, current `revision`, and a
   deterministic plan hash. Authorization and idempotency are checked before
   mutation; stale plans return typed conflicts.
2. Binding plans, audit records, events, and management props contain typed
   references only. Credentials, tokens, authorization headers, and private
   keys are redacted before inbox delivery and never rendered.
3. A grant and Hook subscription belong to one binding. Disconnect retains
   events for that binding; replacement does not inherit the old cursor.
   Acknowledgement is idempotent and cross-binding acknowledgement is rejected.
4. `CRITICAL` attention is an independent overlay and wins over ordinary
   activity color/motion. Stale or unknown health resolves to `OFFLINE`, never
   to an optimistic online state.
5. `OFFLINE` and revoked Presence remain visible with static/low-quality
   material fallbacks. The System Menu placeholder and Classic recovery route
   remain available when the renderer or binding is unavailable.
6. Revoke is a destructive action in the management surface and requires an
   explicit confirmation step. Unavailable Replace/Detach actions expose a
   reason while retaining native keyboard semantics.

## Demo path

1. Open the Spatial route with the live Primary Agent flag enabled.
2. Expand **Primary Agent management** and inspect the Node-scoped slot.
3. Apply an authorized mock MCP binding plan, replace it with a newer plan,
   then detach/revoke. Replaying the same idempotency key is safe.
4. Disconnect the binding, publish a filtered/redacted Hook event, reconnect,
   and acknowledge the retained delivery once.
5. Observe `LISTENING → THINKING → ACTING/WORKING → READY` and the independent
   attention overlay; force stale health to see `OFFLINE` without losing the
   Workspace or Classic recovery path.

M4 can now add typed intents and conversation surfaces on top of this stable
slot, grant, inbox, and Presence boundary.
