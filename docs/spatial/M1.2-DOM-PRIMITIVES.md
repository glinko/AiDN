# M1.2 Spatial DOM primitives

**Status:** Verified implementation slice  
**Scope:** Spatial route only; Classic keeps its existing component and visual
system.  
**Depends on:** [M1.1 Milky Glass token package](./M1.1-MILKY-GLASS-TOKENS.md)

M1.2 provides the first reusable DOM design-system boundary for Spatial. The
primitives keep HTML semantics and operator actions in React markup while the
material system reads a small, declarative surface contract. Placement, camera
state, renderer ownership, and Node authority remain outside this package.

## Surface contract

Surface-bearing primitives accept these independent dimensions:

| Dimension | Values | Purpose |
| --- | --- | --- |
| `depth` | `flat`, `raised`, `floating`, `inset` | Relief and operational hierarchy |
| `glass` | `none`, `soft`, `medium`, `strong` | Transparency and blur level |
| `accent` | `neutral`, `blue`, `violet`, `cyan`, `amber`, `critical` | Restrained semantic accent |
| `radius` | `small`, `medium`, `large`, `pill` | Shape language |
| `emphasis` | `secondary`, `normal`, `primary` | Text and control emphasis |

The contract is emitted as `data-aidn-*` attributes. CSS in
`src/spatial/theme/spatial-theme.css` maps those attributes to versioned M1.1
tokens. Unsupported `backdrop-filter`, reduced-transparency, forced-colors,
and reduced-motion profiles retain opaque, readable, keyboard-safe fallbacks.

## Primitive inventory

The public exports are in
`web/operator-dashboard/src/spatial/primitives/index.ts`:

| Primitive | Native element / role | Contract notes |
| --- | --- | --- |
| `Surface` | `div` | General surface with all five style dimensions |
| `GlassFrame` | `section` | Framed working surface; defaults to floating medium glass |
| `Button` | `button` | Defaults to `type="button"`; action requires an explicit handler |
| `IconButton` | `button` | Requires a non-empty `aria-label`; fixed touch-friendly control size |
| `Input` | `input` | Native input semantics; inset styling is opt-out with `inset={false}` |
| `TextArea` | `textarea` | Native multiline field; inset styling is opt-out with `inset={false}` |
| `InsetField` | `label` + supplied field | Associates label, hint/error, `aria-describedby`, and invalid state |
| `Toggle` | `button[role="switch"]` | Controlled `checked` state and optional `onCheckedChange` callback |
| `Slider` | `input[type="range"]` | Requires `aria-label`; all native range attributes remain available |
| `Tooltip` | `role="tooltip"` | Opens for keyboard focus and pointer hover; trigger gets `aria-describedby` |
| `StatusLabel` / `StatusBadge` | `span[role="status"]` | Text plus `data-aidn-status` (`ready`, `attention`, `critical`, `offline`, `unknown`) |
| `FocusRing` | `div` | Composable `:focus-within` cue without layout movement |
| `RaisedControl` | `div` | Compact raised container using the same surface contract |

`Button` also supports `solid`, `outline`, `ghost`, and `critical` variants,
plus `sm`, `md`, and `lg` sizes. Disabled and loading controls are visibly
muted, removed from the interactive path, and expose `disabled`/`aria-busy`.
Hover, active, `focus-visible`, and disabled states use tokenized changes in
elevation, color, or outline; no state depends on color alone.

## Fixture gallery

`SpatialPrimitivesGallery` is mounted from the lazy Spatial route below the
M1.1 token specimens. It demonstrates:

- explicit button handlers and a non-submitting default button;
- labelled inset `Input` and `TextArea` controls with helper text;
- a keyboard-operable `Toggle` and native `Slider`;
- an icon-only button with a required screen-reader label and tooltip;
- status labels for ready, attention, and offline states;
- a focus ring composed around a working surface.

The fixture is intentionally local and presentation-only. Its values do not
write Workspace or Node state.

## Keyboard and accessibility path

The browser fixture can be completed without a pointer:

1. Enter the Spatial route and tab through profile controls and the labelled
   fields.
2. Focus `Preview intensity`, use `ArrowRight`, and observe the native range
   value update.
3. Focus `Enable live preview`, press `Space`, and observe `aria-checked`.
4. Focus the information `IconButton`; its tooltip appears and is associated by
   `aria-describedby`.
5. Focus `Save workspace`, press `Enter`, and observe the explicit action
   feedback.

Icon-only controls cannot be constructed without an `aria-label` at the
TypeScript boundary. Field labels and helper/error copy remain associated with
the native control, while `role="status"` and `role="alert"` preserve live
feedback semantics.

## Validation

- `tests/unit/spatial-primitives.test.tsx` covers the surface contract,
  native semantics, explicit button behavior, field associations, tooltip
  focus, toggle callback, and status attributes.
- `tests/e2e/spatial-theme.spec.ts` exercises the keyboard-only gallery path in
  Chromium.
- `pnpm test:a11y` audits Classic, the Spatial fallback, and the actual gallery
  with axe.
- `pnpm verify:theme` checks scope, primitive exports, tokenized selectors,
  fallback/profile hooks, and the absence of arbitrary utility literals in the
  fixture.
- `tools/verify-spatial-coverage.py` records M1.2 acceptance IDs
  `M1.2-AC-001` through `M1.2-AC-005`.

Run from `web/operator-dashboard`:

```text
pnpm lint
pnpm typecheck
pnpm verify:theme
pnpm test
pnpm test:theme
pnpm test:a11y
```
