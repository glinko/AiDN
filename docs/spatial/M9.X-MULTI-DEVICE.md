# M9.x Multi-device Workspace and Mobile Navigation

Status: verified frontend contract/service slice, opt-in behind
`spatial_multi_device_sync_enabled`.

M9 makes desktop, tablet, and mobile viewsports of one semantic Workspace.
The semantic world is shared; camera, zoom, focus, selection, opened frames,
quality, gesture state, and presentation geometry are local to each device.
The browser surface is a deterministic adapter seam. Node remains the
authority for durable state, authorization, audit, and transport.

## Implemented boundary

- `spatial.workspace-world.v1` carries canonical refs, semantic anchors,
  relations, clusters, pins, sessions, and a monotonic Workspace revision.
- `spatial.device-viewport.v1` carries local camera/focus/selection/frame and
  gesture state. Updating it never increments the shared revision.
- `spatial.workspace-mutation.v1` and
  `spatial.workspace-mutation-result.v1` carry idempotent actor/device
  operations, base revisions, deterministic stale/topology evidence, and an
  audit reference. Disjoint stale operations merge; same-target topology
  changes return an explicit conflict.
- `spatial.offline-queue.v1` keeps pending semantic operations with
  idempotency, ordered replay, rebase/conflict/reject/discard state, and
  connectivity. It has no protocol/resource action path.
- `spatial.presentation-geometry.v1` selects focus frame, side panel, or
  bottom sheet while preserving semantic references and keyboard/safe-area
  insets.
- `spatial.share-view.v1` is an explicit, expiring audience grant for shared
  focus. It does not transfer authority or overwrite another device's camera.

The implementation lives in
[`web/operator-dashboard/src/spatial/multidevice/`](../../web/operator-dashboard/src/spatial/multidevice/)
and is covered by
[`tests/unit/spatial-multidevice.test.ts`](../../web/operator-dashboard/tests/unit/spatial-multidevice.test.ts).
The flag-gated DOM demo renders desktop and mobile cards over one world so
camera independence, pin propagation, offline replay, gestures, and Share
View can be inspected without a second authority plane.

## Mobile and adaptive behavior

`navigation.ts` is a pure state machine: one-finger pan/rotate, pinch zoom,
tap select, long press empty space → Seed, semantic swipe focus, HOME, Escape,
and arrow-key fallback. Form controls do not capture canvas drags, and mostly
vertical movement can remain page scroll. Reduced motion is represented by the
existing Workspace preference and produces immediate feedback.

Geometry is recomputed locally for desktop/tablet/mobile. Mobile uses a bottom
sheet arrangement with safe-area and keyboard insets; the identity, relation
references, and action semantics stay the same as desktop.
