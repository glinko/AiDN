# M1.3 Hybrid renderer shell

**Status:** Verified implementation slice  
**Scope:** Spatial route only; Classic remains outside the renderer boundary.  
**Depends on:** [M1.2 Spatial DOM primitives](./M1.2-DOM-PRIMITIVES.md) and
[ADR-014](./ADR-014-spatial-ui-technical-architecture.md)

M1.3 establishes the physical split between spatial rendering and interface
markup. `SpatialCanvas` owns empty space, camera input, and the synthetic mock
scene. `SpatialDomOverlay` owns only explicitly interactive DOM regions. Neither
layer becomes an authority for Node or Workspace data.

## Layer contract

`SpatialWorkspace` is the composition root. It renders two fixed siblings:

| Layer | Attribute | Default pointer behavior | Responsibility |
| --- | --- | --- | --- |
| Canvas | `data-spatial-layer="canvas"` | `auto` | WebGL2/R3F scene, mock picking, orbit/pan input |
| DOM overlay | `data-spatial-layer="dom-overlay"` | `none` | GlassFrames, controls, text, status and recovery actions |

The overlay does not create a transparent hit-test wall. A descendant must be
wrapped in `SpatialInteractive` (which emits `data-interactive="true"`) to opt
into pointer events. This keeps empty overlay space available to the canvas.
The canvas and all renderer-created elements are `aria-hidden="true"` and
`tabIndex="-1"`; keyboard focus remains in the DOM control path.

## Viewport and DPR

`useSpatialViewport` observes the workspace with `ResizeObserver` and also
listens for `resize` and `orientationchange`. It exposes:

- width and height in CSS pixels;
- `portrait`/`landscape` orientation;
- a monotonic revision for measurement changes;
- a bounded DPR: `1.25` on narrow/mobile viewports and `1.5` on desktop.

The selected Node is owned by `SpatialWorkspace`, not by the viewport hook, so
measurement and orientation changes do not clear selection or open frames.
The hook accepts zero-sized observer entries as a signal to read the browser
viewport, which keeps jsdom and fixed-layer layouts deterministic.

## Renderer and fallback behavior

`SpatialCanvas` prefers R3F `Canvas` with `frameloop="demand"`, an explicit
camera, and the bounded DPR. The mock scene contains two selectable synthetic
objects (`mock-agent` and `mock-endpoint`) and no Dashboard API calls.

When a browser reports no usable WebGL2 context, the component keeps the same
fixed canvas contract and draws a lightweight 2D mock scene. This is a visual
capability fallback, not a second data path. A short loading status is exposed
while the capability is measured.

`SpatialRendererErrorBoundary` catches render-time failures. Its fallback is a
DOM `role="alert"` surface with Retry and Return-to-Classic actions. The log is
categorical (`renderer-init-failed`) and never exposes GPU details. Retrying
remounts only the renderer boundary; selected state and the surrounding DOM
remain intact.

## Demo behavior

The Spatial route mounts a fixed mock scene behind the existing token and
primitive gallery. The gallery reserves a transparent, labelled scene lane so
the synthetic Nodes remain discoverable in the first viewport. `Open GlassFrame`
appears in the DOM overlay. Once opened,
the GlassFrame reports the selected synthetic Node, viewport dimensions, DPR,
and measurement revision. Its action button proves that a DOM control can be
activated without changing canvas state.

The canvas fallback accepts a pointer selection, opens the GlassFrame, and
keeps the selected label after a viewport rotation. On a real WebGL2 browser,
the same selection contract is handled by R3F mesh events.

## Validation

- `tests/unit/spatial-workspace.test.tsx` covers layer markers, DOM activation,
  selection persistence across orientation changes, DPR caps, focus exclusion,
  and the renderer error fallback.
- `tests/e2e/spatial-theme.spec.ts` covers the Chromium keyboard path, pointer
  boundary CSS, mock selection, DOM action, resize, and orientation behavior.
- `pnpm test:a11y` audits the fallback, Classic shell, and the full Spatial
  gallery with the canvas excluded from the accessibility tree.
- `pnpm verify:theme` checks that workspace, canvas, overlay, viewport, and
  error-boundary contracts remain present alongside the M1.1/M1.2 scope rules.
- `tools/verify-spatial-coverage.py` records `M1.3-AC-001` through
  `M1.3-AC-005`.
