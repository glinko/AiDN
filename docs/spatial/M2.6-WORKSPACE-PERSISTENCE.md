# M2.6 — Workspace API and Persistence

M2.6 provides the minimum canonical CRUD surface without allowing arbitrary
layout mutations. `SpatialWorkspaceRepository` has a deterministic in-memory
implementation for acceptance and an HTTP adapter for the Node endpoints.

## Endpoint contract

- `GET /operators/spatial/workspace`
- `GET /operators/spatial/workspace/changes?after_revision=N`
- `POST /operators/spatial/workspace/operations`
- `PUT /operators/spatial/workspace/presentation`
- `POST /operators/spatial/workspace/presentation/reset`
- `GET /operators/spatial/entities/:canonical_ref`
- `GET /operators/spatial/relations/:relation_ref`

Semantic operations require an expected revision, operation ID, idempotency key
and actor reference. Successful semantic writes produce an audit/change record;
presentation-only writes return `protocol_event_emitted: false`.

## Acceptance

| Acceptance ID | Criterion | Validation | Status | Deferred reason, if any |
| --- | --- | --- | --- | --- |
| `M2.6-AC-001` | Snapshot and changes endpoints are revisioned and Node-scoped | repository and HTTP adapter tests | verified | None |
| `M2.6-AC-002` | Shared mutations require revision and idempotency | validation, stale and duplicate-operation tests | verified | None |
| `M2.6-AC-003` | Authorization and audit/change records are enforced | unauthorized operation and change record assertions | verified | None |
| `M2.6-AC-004` | Wrong Node and Agent replacement races are rejected | repository conflict tests | verified | None |
| `M2.6-AC-005` | Partial persistence failures do not commit | fail-next-write transaction test | verified | None |
| `M2.6-AC-006` | Reload and corrupt presentation recovery are safe | reset fallback and reference lookup tests | verified | None |

Device viewport state remains local to its `device_id`; two clients can read
one semantic snapshot while persisting independent presentation records.
