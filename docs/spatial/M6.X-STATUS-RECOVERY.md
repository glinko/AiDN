# M6 — Node Status, System Menu, and Recovery

M6 is implemented as a Node-owned observation and command boundary. The
Primary Agent and the WebGL renderer are optional participants; neither is a
source of truth for Node state.

## Implemented seams

- `web/operator-dashboard/src/spatial/status/aggregator.ts` contains `SpatialStatusAggregator`.
  Probes are direct, typed inputs. A failed probe becomes an explicit
  `UNKNOWN` component while healthy observations remain in the same snapshot.
  Cached snapshots are marked `STALE` and `cached`, never presented as current
  `ONLINE` evidence. Evidence and details are bounded and redacted at the
  boundary.
- `web/operator-dashboard/src/spatial/status/recovery.ts` contains the plan/apply command seam and
  `StatusWorkspaceBridge`. Recovery plans bind the Node, target, action,
  revision, capability, consequence, and idempotency key. Apply validates the
  plan again, requires confirmation for destructive actions, records an audit
  reference, and returns an idempotent result.
- `web/operator-dashboard/src/spatial/status/SystemMenu.tsx` is a permanent DOM shell with Status,
  Primary Agent, Node Settings, Appearance, Network, Wallet, Permissions, and
  Advanced sections. Status Summary and Details use the same snapshot revision,
  expose text state/freshness, and keep raw evidence bounded. Escape/focus
  handling and the mobile bottom-sheet frame are part of the component.
- `SpatialWorkspace` mounts the menu beside the renderer boundary. Renderer
  errors therefore leave the menu and semantic Workspace state available. The
  route boundary also has a minimal DOM fallback menu for WebGL2 failure.
- `web/operator-dashboard/src/spatial/contracts/index.ts` defines `spatial.node-status.v1`,
  `spatial.recovery-command.v1`, and `spatial.recovery-result.v1`; the event
  gateway recognizes status and recovery event types. HTTP clients expose the
  typed recovery plan/apply seam without allowing presentation code to bypass
  authorization.

## Safety rules

1. Status is factual evidence, not a second dashboard and not a conversation
   with the Agent.
2. `UNKNOWN`, `STALE`, `PARTIAL`, `UNAVAILABLE`, and authorization-redacted
   values remain explicit. Missing evidence is never upgraded to `ONLINE`.
3. `SHOW_IN_WORKSPACE` resolves an existing canonical reference and asks for a
   temporary focus. It does not create a duplicate entity or mutate world
   coordinates; stale, unavailable, absent, and wrong-workspace cases return a
   typed details/rejection state.
4. Recovery actions are never triggered by remote content or by a status row
   alone. They require a current plan, capability, and consequence-appropriate
   confirmation, then produce an audit-linked result.
5. The rollout flag `spatial_status_enabled` is presentation-only. Node
   authorization and the Classic control plane remain authoritative.
