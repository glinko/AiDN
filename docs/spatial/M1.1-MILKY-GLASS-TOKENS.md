# M1.1 Milky Glass token package

**Status:** Verified implementation slice  
**Token version:** `spatial.tokens.v1`  
**Scope:** Spatial route only; Classic remains the existing dark control-plane
surface.

## What shipped

The versioned package lives in
`web/operator-dashboard/src/spatial/theme/tokens.ts`. It names the material
system's color roles, opacity, elevation, radius, blur, spacing, typography,
and motion values. Text roles are intentionally opaque and AA-safe on their
specimen backgrounds; the secondary and muted values are darker than the
initial visual proposal so legibility does not depend on glass translucency.

The CSS implementation in `spatial-theme.css` is loaded by
`SpatialThemeBoundary`, a wrapper imported only by the lazy Spatial route. All
custom properties and selectors are prefixed with `.aidn-spatial-theme`, so
the token variables cannot leak into Classic. The boundary also exposes the
version and active quality profiles as `data-aidn-*` attributes for inspection.

## Quality profiles and fallbacks

- Standard is the light Milky Glass profile: translucent surfaces, soft
  elevation, and a restrained backdrop blur.
- High contrast darkens secondary/muted roles, strengthens the separator, and
  makes surfaces more opaque while retaining the same hierarchy.
- Reduced transparency replaces translucent fills with `#f3f6fa` and sets all
  Spatial blur variables to `0px`. The explicit profile and the browser's
  `prefers-reduced-transparency` preference use the same fallback.
- Browsers without `backdrop-filter` get the opaque fallback before the
  `@supports` enhancement is applied. Forced-colors mode maps surfaces to
  system `Canvas`/`CanvasText` and removes decorative shadows.
- `prefers-reduced-motion` shortens CSS transitions and animation to a
  one-frame response; the Motion entrance also skips its travel.

No new component may add an arbitrary visual literal when a token or semantic
class exists. Token-derived inline color values are used only by the contrast
specimen to show the exact values under test.

## Fixture gallery

`SpatialTokenGallery.tsx` is the Storybook-equivalent fixture page mounted by
`spatial-route.tsx`. It includes the required token preview, contrast table,
motion replay, and blur/fallback specimens, plus the existing opt-in renderer
probe. The profile buttons are keyboard-accessible and update only the Spatial
boundary.

The contrast specimen currently reports:

| Role | Foreground / background | Ratio | Target |
| --- | --- | ---: | --- |
| Primary | `#223553` / `#fbfcfe` | 12.02:1 | WCAG AA |
| Secondary | `#4f607b` / `#f6f8fb` | 6.00:1 | WCAG AA |
| Muted | `#5d6d83` / `#eef2f6` | 4.69:1 | WCAG AA |

## Validation

- `tests/unit/spatial-theme.test.tsx` checks the version, token groups, exact
  contrast calculation, profile boundary, and fixture controls.
- `pnpm test:a11y` checks the actual token gallery in Chromium in addition to
  the existing Classic and direct-route fallback surfaces.
- `tests/e2e/spatial-theme.spec.ts` opens the real lazy route in Chromium and
  exercises standard, high-contrast, reduced-transparency, motion, and opaque
  fallback specimens without a live Node.
- `pnpm verify:theme` rejects global theme selectors and unscoped fixture class
  names, and checks that the profile/fallback hooks remain present.
- Run locally from `web/operator-dashboard`:

  ```text
  pnpm lint
  pnpm typecheck
  pnpm verify:theme
  pnpm test
  pnpm test:theme
  ```
