# M3.1 — Primary Agent Slot domain model

M3.1 introduces the canonical Node-scoped Primary Agent Slot without making
the browser, a model name, or a runtime binding authoritative. The slot keeps
references to the current binding, capability grant, hook subscription, and
durable inbox; Agent Identity and runtime binding records remain separate.

## Contract

`spatial.primary-agent-slot.v1` contains:

- stable `slot_id` and owning `node_id`;
- nullable `current_binding_id`;
- explicit `lifecycle_state` (`UNASSIGNED`, `BINDING`, `CONNECTED`,
  `DEGRADED`, `DISCONNECTED`, or `REVOKED`);
- monotonic `revision` and audit timestamps/actor references;
- separate capability, hook, and durable-inbox references.

No credential material or opaque runtime payload is accepted by the binding
reference seam. Unknown additive contract fields are stripped before a value
reaches the repository.

## Domain and persistence seam

`InMemoryPrimaryAgentSlotRepository` is the deterministic acceptance adapter for
the future Node service. It enforces one slot per Node, validates binding
ownership, rejects stale revisions and idempotency-key reuse, serializes
concurrent updates through a commit-time revision check, and records an audit
change for every semantic operation. `bind` and `replace` commit the new
binding and slot state together; `detach` and `revoke` clear active grants but
retain the durable inbox reference.

`serialize()`/`restart()` exercise reload without losing the slot, binding
registry, audit changes, or idempotent operation records. Missing or cross-Node
binding references fail with a typed `CORRUPT_BINDING`/`NODE_MISMATCH` conflict
before a slot is exposed. Workspace data is not stored inside this model, so
Agent replacement cannot delete or rewrite the Node-owned Workspace.
