# M1.7 Camera and navigation prototype

**Status:** Verified implementation slice  
**Scope:** Device-local viewport state; no Workspace mutation.  
**Depends on:** [M1.6 mock spatial entities](./M1.6-MOCK-ENTITIES-PICKING.md) and [ADR-014](./ADR-014-spatial-ui-technical-architecture.md)

`camera.ts` defines the local `SpatialCameraState` (`x`, `y`, `zoom`,
`focusId`, and a monotonic transition token) and clamps every command to the
same bounds. `HOME` returns the Primary Agent view and the named
`FOCUS_PRIMARY_AGENT` command focuses the central Presence directly. Focusing an entity copies
its position into the camera only; the entity object is never mutated. Return,
zoom, pan, and rotate commands all create a new bounded state.

`SpatialNavigationController` is the DOM keyboard equivalent of canvas
gestures. It exposes visible HOME, Focus selected, Back from focus, and zoom
controls, plus Home/Escape/+/- key handling. The R3F path uses OrbitControls
with bounded distance/polar angles; the fallback maps drag/wheel input to the
same pure camera functions. Reduced motion makes the transition duration zero
and the deterministic replay avoids an animation dependency.

## Acceptance evidence

| Criterion | Evidence |
| --- | --- |
| HOME returns Primary Agent | `HOME_CAMERA` and the visible HOME control share one pure command. |
| Focus does not alter world coordinates | `focusSpatialEntity` only returns a camera state; unit test snapshots the entity position. |
| Rapid commands remain valid | Every pan/rotate/zoom/focus operation calls `clampSpatialCamera`; bounds are unit-tested. |
| Keyboard equivalents exist | Navigation container handles Home, Escape, and +/- and exposes native buttons. |
| Transition cancellation is safe | `transitionToken` increments each command; the local state update replaces prior transitions without timers in the camera layer. |

The camera state is rendered as `data-aidn-camera-focus` and
`data-aidn-camera-zoom` so browser evidence can assert HOME → focus → return.
