# Расширение ранбука: от запроса до опубликованного Endpoint

Статус: проверка текущего кода и проект расширения протокола. Это дополнение
к [гайдбуку установки](ai-assisted-installation-agent-guidebook.md), а не
утверждение, что все перечисленные поля уже доступны через MCP или frame.
Основание: локальная версия `ab2b1070`; проверка реализации, без установки
моделей и изменений конфигурации ноды.

## 1. Что сейчас отсутствует

| Область | Подтверждено кодом | Что добавить |
| --- | --- | --- |
| Завершение публикации | `installation_apply` заканчивается `start_private_endpoint`; `aidn.endpoint.publish` существует отдельно | Явный переход от установки к конфигурации, validation и публикации; проверка результата в реестре |
| Применение ответов | `_create_private_endpoint_from_installation_plan` задаёт имя `(local)`, private, validation disabled, external false; не передаёт выбранный тариф | Перенос подтверждённых полей в конечную конфигурацию и сверка каждого поля. Промежуточный private Endpoint не означает выполнение запроса публикации |
| Аудитория | Endpoint поддерживает private/shared/public, discoverable, `shared_with_wallet_ids`, `accepts_external_requests`; установочная форма предлагает private/public и один флаг external-without-allowlist | Разделить видимость, обнаружение, приём запросов и конкретных разрешённых потребителей |
| Тип задачи | Список установочных провайдеров фиксирован: llama.cpp, Ollama, vLLM; forecast создаёт `llm_text` | Ветвление по возможностям адаптера для LLM/VLM, STT/TTS, embeddings и других типов; неподдержанный тип не пропускать по LLM-ветке |
| Тариф | Форма содержит один компонент и четыре единицы; `RateCardV2` поддерживает несколько компонентов и аудио/изображения/другие единицы | Составной тариф и доказательство доступности измерений для каждого компонента |
| Поведение Endpoint | В модели есть streaming, timeout, session policy, profile; в установочной форме их нет | Включить эти параметры в полный план и в применяемую конфигурацию |
| Изменение опубликованного Endpoint | Есть configuration hash, snapshots и supersede validation; форма ограничивает редактирование опубликованной конфигурации | Отдельный путь ревизии, повторных проверок и замены публикации |
| Подтверждение | Есть подтверждение формы и отдельные MCP plan/apply; JSON сам по себе не даёт полномочий | Долговечная запись утверждения полного намерения и связь с разрешёнными шагами исполнения |
| Файл | JSON — существующий канонический план; в просмотренном установочном пути нет CSV round-trip | Экспорт полной ревизии, типизированный импорт правок, повторный preview и утверждение |

Есть и ошибки точности формы, которые следует исправить до расширения:

- Нормализатор контекста восстанавливает стандартные fallbacks, если список
  пуст: снятие обеих галочек не сохраняет запрет понижения контекста.
- Проекция использует `gpu_layers or "auto"` и `offload or "auto"`:
  явные `0` и `false` показываются как `auto`.
- При смене источника модели форма передаёт прежние expected SHA256/bytes.
  Эти доказательства нужно пересчитать для нового артефакта до утверждения.
- Таблица старого гайдбука показывает `ask`, хотя форма отображает конкретные
  рекомендации. Нужно различать unresolved, recommended и operator-confirmed.

Источники проверки: `installation_onboarding.py`, `mcp/interface_tools.py`,
`mcp/steward_tools.py`, `service.py`, `endpoints/models.py`,
`endpoints/endpoint_application_service.py`, `pricing/models.py`,
`runtime_parameter_policy.py`, `mcp/server.py` в `src/aidn_hypervisor/`.

## 2. Правило минимального опроса

Агент сначала извлекает решения из текущего запроса и ранее явно заданных
предпочтений оператора. Не спрашивает повторно известное. Технические факты
получает через MCP; отсутствие ресурса или измерения не заменяет догадкой.

На первом экране — до пяти смысловых групп, а не отдельный вопрос на каждый
параметр. Группы показывают предзаполненные рекомендации и краткие последствия.
Дополнительный вопрос нужен только при неоднозначной цели, конфликте,
невыполнимости или отсутствии критического значения. Финальное подтверждение
охватывает явно показанные рекомендации, оставленные пользователем без правок.

| Критическая группа | Что решает оператор | Когда нужно уточнение |
| --- | --- | --- |
| Результат и аудитория | Только Bundle, запущенный личный Endpoint, shared или публичная публикация; кто может обращаться | Цель неясна; shared выбран без списка; видимость противоречит политике доступа |
| Бесплатно/платно | Режим, единица и цена; дополнительные сборы, если нужны | Для платного нет подтверждённого тарифа; измерения провайдера не покрывают тариф |
| Валидация | Нужна ли проверка/сертификация; применимый профиль и затраты | Профиль недоступен, результат неудовлетворителен или требуется расход сверх утверждённого |
| Ресурсный компромисс | Целевой контекст, нижняя граница; цель «качество/задержка/параллельность», если она влияет на подбор | 128K → 64K → 32K не помещается; модель не поддерживает выбранный размер; нужна другая модель/квантизация |
| Влияние на текущую работу | Сосуществование или замена конкретного runtime, допустимое прерывание | Замена действительно нужна; есть активные сессии; неизвестно, что разрешено остановить |

Выбор «внешние запросы без allowlist» остаётся явным внутри группы аудитории.
Бесплатность не означает открытый доступ; публикация в каталоге не означает
приём запросов от всех. Если оператор уже сказал «платный публичный Endpoint»,
форма должна сохранить это намерение, а не предлагать private/free вопреки ему.

Рекомендуемый базовый профиль при отсутствии предпочтений: private, free,
validation required при поддержке профиля, внешние запросы запрещены,
сосуществование без остановки существующих runtime. Неподдержанную validation
обозначать как препятствие/выбор альтернативы, а не выдавать за выполненную.

## 3. Полный каталог параметров без длинного опроса

Форма имеет краткую сводку, критические решения и раскрываемые расширенные
параметры. Полный файл содержит все применимые параметры, в том числе скрытые
за раскрываемыми секциями. Скрытая секция не должна скрывать стоимость,
расширение доступа или остановку работающего сервиса.

| Секция | Параметры полного плана | Как получать рекомендации |
| --- | --- | --- |
| Цель | operation kind, node, существующий Endpoint/Bundle, конечное состояние | Из запроса и текущего инвентаря; новые идентификаторы после создания — результат исполнения |
| Модель | repo, revision, файлы/shards, формат, quantization, checksum, bytes, дополнительные проекторы/адаптеры | Из метаданных и возможностей выбранного провайдера; недоступные факты обозначить unknown |
| Провайдер | Тип, instance, версия, поддерживаемые modality/API, способ установки | Из MCP capability/installation schema; переиспользовать совместимое существующее размещение |
| Диск и загрузка | Свободное место, временный запас, размещение, повторное использование артефакта, доступ к закрытому источнику | Из измерений; секреты только как ссылки на настроенные credentials, не внутри CSV/JSON |
| Runtime | Контекст, max tokens, GPU/CPU, KV-cache, GPU memory budget, concurrency, batch и другие поддержанные параметры | Из схемы адаптера и оценки ресурсов; явно показывать итог auto; не добавлять неизвестные флаги |
| Запросы | streaming, timeout, temperature/top_p и применимые sampling-поля | Из возможностей runtime; streaming рекомендовать при подтверждённой поддержке; таймаут учитывать вместе с очередью |
| Полномочия потребителя | `consumer_editable`, min/max для каждого параметра запроса | Использовать каноническую runtime parameter policy; изменения размещения оставлять оператору |
| Сессии и очередь | max concurrent sessions, busy/queue, idle timeout, max duration, local agent use | По ресурсам и предполагаемой нагрузке; различать сессии и параллельные запросы |
| Доступ | private/shared/public, discoverable, external requests, wallet allowlist | Из решения оператора; дополнительные лимиты/аутентификацию показывать как исполнимые только при наличии backend |
| Оплата | Все компоненты RateCard, единицы, divisor, rounding, minimum charge, применимые session charges/deposits | Из подтверждённого тарифа и измеряемого usage; цена не угадывается; показывать понятный расчёт примера |
| Профиль публикации | Имя, описание, задачи, языки, capabilities, ограничения, примеры | Агент составляет черновик по проверенным возможностям; не обещает неизмеренную скорость/качество |
| Проверки | health, пробный inference, применимая validation, hash конфигурации, готовность wallet/registry | Из MCP-проверок; smoke test и сертификация — разные результаты |
| Замена и восстановление | Целевые runtime, drain активных сессий, окно, предыдущая ревизия, условия rollback | По текущим зависимостям; операции drain/rollback требуют исполнимого адаптера, не только текста плана |

Это каталог расширения. Наличие поля в Endpoint-модели не доказывает, что оно
уже передаётся установочным MCP-путём. Для каждой возможности адаптер должен
указать supported, unsupported или unknown; недоступный параметр не должен
выглядеть успешно применимым.

## 4. Варианты запросов и границы самостоятельности

| Запрос/событие | Действие агента |
| --- | --- |
| «Установи модель» | Уточнить конечный результат только при необходимости, собрать рекомендуемый план |
| «Опубликуй уже установленную» | Переиспользовать подходящие Bundle/runtime; исключить лишнюю загрузку и установку |
| «Сделай доступной этим пользователям» | Предложить shared с конкретным списком; проверить его перед утверждением |
| «Поставь другую цену/лимит/контекст» | Показать diff, влияние на ресурсы и validation; построить путь ревизии опубликованной конфигурации |
| «Замени/обнови модель» | Закрепить новую версию, показать прерывания и применимый rollback; не следовать плавающему latest автоматически |
| «Ускорь/уменьши память» | Сначала измерить; предложить сравнение конфигураций. Другую quantization или модель утвердить отдельно, если не включены в план |
| «Временно закрой/сними с публикации» | Различить приём новых запросов, discoverability, остановку runtime и удаление; показать выбранный эффект |
| «Продолжи после ошибки» | Восстановить job/state, проверить уже совершённые эффекты; повторить только оставшийся разрешённый шаг |
| Нет места/памяти/доступа к источнику | Показать конкретный дефицит; предложить исправленный план; не удалять модели и не менять доступ автоматически |
| Ошибка validation/регистрации | Сохранить подтверждённый статус достигнутых шагов; не сообщать «опубликовано»; показать причину и допустимые действия |
| Потеря связи/перезапуск агента | Read-back перед повтором; не создавать дубликаты Bundle, Endpoint и оплачиваемых операций |
| Несколько установок одновременно | Отдельные plan/job IDs и контроль ресурса; текущий единственный configured plan path требует расширения для независимых планов |

Разрешённая адаптация задаётся в плане: например, 128K → 64K → 32K без смены
модели, тарифа и доступа. Значения, полученные из измерений, не являются
разрешением расширить эту границу. Невыполнимый прогноз нельзя назвать успешным;
unknown нужно явно показать до выполнения зависимого шага.

## 5. Файл и утверждение

Канонический формат — JSON: он сохраняет вложенность, типы, массивы тарифов и
условия. CSV — удобная полная табличная проекция для просмотра и правок.
Оба представления относятся к одной ревизии. Пример колонок будущего экспорта:

```csv
plan_id,revision,path,type,value_json,unit,origin,editable,reason
example,1,runtime_policy.context_length.requested,integer,131072,tokens,recommended,true,Target context
example,1,runtime_policy.context_length.fallbacks,array,"[65536,32768]",tokens,operator_policy,true,Approved fallback order
example,1,publication_policy.visibility,string,"""private""",,recommended,true,Owner access
```

Пример иллюстрирует формат, не является готовым планом установки. Для
экспортированных пользовательских строк нужна защита от CSV formula injection,
с обратимым кодированием без изменения канонических значений. Импорт не запускает
операции: строго проверяет типы, неизвестные/повторные пути, размеры, ревизию,
read-only поля и показывает diff новой версии для утверждения.

Предлагаемый конверт полного плана: schema version, plan ID/revision, цель,
исходные факты, рекомендации и их основания, итоговые значения, допустимые
fallbacks, ожидаемые эффекты/затраты, preconditions, разрешённые операции и
условия остановки. Происхождение значения хранится отдельно: explicit request,
saved preference, measured, recommended, operator edited.

Поток:

1. Разобрать цель → получить факты → проверить совместимость и предварительные ресурсы.
2. Выпустить один frame с критическими решениями и всеми расширенными полями.
3. Принять правки → пересчитать зависимые параметры → выпустить окончательный preview и JSON/CSV.
4. Утвердить полный intent hash, область действий и условные ветви один раз.
5. Последовательно выполнять MCP plan/apply, фиксируя job и проверенные результаты.
6. Подготовить конечную Endpoint-конфигурацию → выполнить требуемые проверки → опубликовать, если это входит в утверждённую цель и разрешено MCP.
7. Проверить реестр, конфигурацию и доступный путь inference; показать Endpoint ID, адрес, тариф, доступ и фактически выбранный контекст.

Утверждение намерения и изменяющийся журнал исполнения — разные записи.
Progress/job ID не требует нового согласия; изменение модели, цены, аудитории,
целей остановки или выход за утверждённые ресурсы/расходы требует новой ревизии
и показа diff. Если новые измерения укладываются в утверждённые условные ветви,
достаточно записать, какая ветвь выбрана, без повторения анкеты.

Одно пользовательское утверждение не отключает существующие MCP approvals.
Для прохода без повторных диалогов нужен исполняемый механизм ограниченного
разрешения на конкретный план. Ранбук сам по себе такой механизм не создаёт.
Публикация может быть отдельной MCP-операцией в пределах заранее утверждённого
плана; это не обязательно отдельный повторный вопрос пользователю.

## 6. Очерёдность реализации и критерии готовности

1. Исправить round-trip формы и перенос подтверждённых параметров в результат.
2. Добавить полный типизированный план, условные группы и capability-проекцию.
3. Реализовать цепочку configuration → validation → publish с read-back.
4. Связать утверждение неизменного намерения с исполнением, восстановлением и MCP approvals.
5. Добавить JSON/CSV экспорт/импорт; затем расширять адаптеры, ревизии и дополнительные типы моделей.

Проверять реальные сценарии: private/free без уточнений; shared с allowlist;
paid с несколькими компонентами; отказ 128K и успех 64K; явный запрет fallbacks;
0 GPU layers и offload=false; смена источника с новой integrity metadata;
замена при активных сессиях; обновление опубликованной конфигурации; отсутствие
validation-профиля; сбой публикации после успешного запуска; восстановление
после перезапуска; устаревший/изменённый CSV и конфликт ревизии; неподдержанный
тип модели. Для каждого параметра проверять цепочку «показано → утверждено →
передано адаптеру → подтверждено в фактической конфигурации».
